## Signature interaction

The native request choices lead to one message-signing action. Real received events populate an expanded result and a five-field enforcement summary: Agent requested, Owner's limit, Result, Reason and Tx. Important final outcomes use a bounded polite announcement; elapsed time is ordinary text. The interface never equates a missing receipt with proof of no submission.

## Information hierarchy

1. Current agent, wallet readiness and observation freshness.
2. One request composer and the owner's actual policy.
3. The visitor's actual model decision, outcome and receipt.
4. Shared activity, then integration detail and observed RPC traffic.
