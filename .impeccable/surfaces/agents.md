## Interaction and state

New setup uses one coordinator transaction to create and fund the distinct resources. Default policy is 5 kUSD per trade, 100 kUSD per day and 2% maximum pool price impact. An actual create estimate, 20% gas margin and current fee data determine the displayed budget, including the owner's 0.0001 Sepolia ETH gas forward. Creation stays disabled when the balance or estimate is missing or insufficient; it offers a verified ETHGlobal faucet link and the funded-demo alternative. A fresh check precedes signing and transaction submission.

The six-step checklist is retained only for earlier workspaces, under their compatibility flow. Coordinator workspace discovery, deterministic legacy discovery, actual ENS records, factory vault ownership and authorization determine completion. Saved transaction hashes provide evidence links, not boolean flags.

The new key is encrypted at rest in browser storage with AES-GCM and a key derived from a verified local owner signature through HKDF. Its message binds the canonical origin, Sepolia, owner, agent and local-encryption purpose. The signature is never stored or sent to Fly.io and is distinct from run admission. A later session uses the same wallet/message to unlock; stable EOA signatures are required. Earlier passphrase-encrypted records remain supported.

The first-run path requires neither a password nor a manual backup. Optional encrypted export supports moving or restoring the browser record. Clearing storage without that export loses the random restricted key; the owner still controls vault withdrawals. This is not recovery from the owner address alone. No raw owner or agent private-key input is presented.

An unlocked key exists only in the active page; changed owner or workspace clears it. Pending asynchronous operations track context changes so switching away and back cannot silently resume an old unlocked operation.

The completed task area contains the two fixed scenario choices and one explicit run action. A five-field result states Agent requested, Owner's limit, Result, Reason and Tx. A reverted receipt and a preflight simulation reason are separate facts. The last ten results are saved per workspace, with a read-only refresh action for a saved run; a resumed prepared request is never automatically signed.

## Truth and boundaries

The ENS namespace is `kusari-pramod.eth`; the parent registry is a disclosed trust dependency. Dedicated resolvers and labels belong to the owner wallet. Vault owner and agent are immutable, so agent rotation requires a new vault.

The personal key remains browser-held and noncustodial with respect to the server; the shared demo's hosted agent key is custodial. Fly.io prepares Gemini proposals and relays browser-signed personal transactions through Anon-RPC/Nox. Keep the personal workspace page open for an operation; it is not an unattended background runner. Observed request, submission and HTTP-failure counters do not prove anonymity. Transactions remain public. Browser policy snapshots, wallet setup transactions and owner controls use their configured reader/provider, outside the agent-service routing boundary.

Use testnet funds only. The interface does not claim audited custody, arbitrary trading/chat or arbitrary ENS-domain onboarding. A shared-demo visitor remains separate from an owned workspace, and shared-owner controls remain explicit in the application header.
